# bloom — First-time onboarding: implementation plan

Status: ready for implementation by a coding-design agent.
Goal: a full-screen welcome intro (Option A) for first-time users, plus a light progressive-disclosure nudge (Option C). The design agent is free to refine copy, visuals, and motion; the structural decisions in section 2 and the hooks in sections 5–7 must not change without discussion.

---

## 1. Goal

New users land on a login screen, create an account, and land directly in the Track view with 10 default trackers and no explanation. This plan adds:

- **A — Welcome intro**: a full-screen, slide-based overlay shown once, immediately after account creation, explaining the app in ~45 seconds.
- **C — First check-in nudge**: one dismissible tip banner in the Track view for users with no data yet.
- **Help replay**: a "How bloom works" card in the Manage view that replays the intro any time.

## 2. Locked decisions

| # | Decision |
|---|---|
| 1 | Intro triggers **after account creation** (on the `SIGNED_IN` event, gated by a `bloom.justSignedUp` flag set at signup). Not shown to signed-out visitors on the auth screen. |
| 2 | Format: full-screen slide overlay, hand-rolled vanilla JS + CSS. **No libraries** (CSP: `script-src 'self'` + jsdelivr only). |
| 3 | Persistence: `localStorage['bloom.onboarded'] = '1'` set on finish **or skip**. `localStorage['bloom.justSignedUp'] = '1'` is transient — set at signup, consumed on the next `SIGNED_IN`. |
| 4 | `clearLocal()` in app.js wipes only `bloom.trackers` / `bloom.entries` / `bloom.deletedTrackers` — the onboarding flags **survive sign-out**. Returning users are not re-onboarded; a fresh account (new signup flag) is. |
| 5 | Skipping marks onboarded (skip = consent to dismiss). Closing the tab mid-intro does **not** mark onboarded, but the transient flag is consumed, so it will not auto-reappear — the user can replay via Help. Acceptable; noted so it is a deliberate choice. |
| 6 | Existing empty states are kept as-is and are the "C" fallback. The nudge banner (section 9) is the only new progressive element. |

## 3. UX flow

```
Open app → auth screen → Create account (sets justSignedUp flag)
  → SIGNED_IN fires
      → applyAuthState() pulls cloud data, renders Track view
      → onboarding.onSignedIn(): if justSignedUp && !onboarded → show overlay
          → user: Skip | ←/→ navigate 8 slides | "Let's start 🌸"
          → finish or skip → set onboarded, close, focus back to app
          → inject first-check-in tip into Track view (if entries empty)
Manage view → "How bloom works" card → onboarding.start({replay:true})
```

## 5. Markup spec (`index.html`)

### 5.1 Onboarding overlay — end of `<body>`, after the auth screen div

```html
<div id="onboarding" class="hidden" role="dialog" aria-modal="true" aria-labelledby="onboarding-title">
  <div class="onboarding-card">
    <button id="ob-skip" class="onboarding-skip" aria-label="Skip intro">Skip</button>
    <div class="onboarding-slides">
      <!-- 8 <section class="onboarding-slide"> children, one per slide (section 8) -->
    </div>
    <div class="onboarding-dots" id="ob-dots"><!-- generated by JS from slide count --></div>
    <div class="onboarding-nav">
      <button id="ob-back" class="mini-btn">Back</button>
      <button id="ob-next" class="save-btn">Next</button>
    </div>
  </div>
</div>
```

- Slides live in the DOM statically (not JS-injected) so the structure is reviewable and editable by the design agent.
- Each slide: a `<h2 id="ob-title-N">` heading + one illustration block + one short paragraph. Slide 1's heading is `#onboarding-title` (aria reference).
- JS toggles the `hidden` attribute on the overlay and per-slide, and manages the dots. All copy is centralized in one `SLIDES` array in onboarding.js (see 8.1) that the agent can edit; the DOM slides render from it OR are written statically — **pick one**: recommend rendering slides from the `SLIDES` array so copy lives in exactly one place.

### 5.2 Help card — Manage view (`#view-manage`)

Static card, placed after the theme card area / near the backup card:

```html
<div class="backup-card">
  <h3 class="checkin-title">🌸 How bloom works</h3>
  <p class="hint">New here, or want a refresher? Replay the quick intro.</p>
  <button id="help-btn" class="save-btn">Replay intro</button>
</div>
```

`onboarding.js` binds `#help-btn` → `start({ replay: true })` (no flags written on replay).

### 5.3 Tip container — Track view (`#view-track`)

Static empty container **before** `#entry-list` (survives `renderTrack()` innerHTML clears):

```html
<div id="first-tip"></div>
```

## 6. `onboarding.js` — API & behavior

Expose a single global:

```js
window.bloomOnboarding = {
  onSignedIn(),              // consume justSignedUp → maybe start intro
  start({ replay }),         // open overlay, wire nav; replay=true → no flag writes
  showFirstCheckinTip(),     // inject nudge banner if entries empty & not dismissed
};
```

### Behavior spec

- `onSignedIn()`: if `localStorage['bloom.justSignedUp']` → remove it; if `!localStorage['bloom.onboarded']` → `start({replay:false})`.
- `start()`:
  - Remove `hidden` from `#onboarding`; set `aria-modal`, focus the Skip or Next button.
  - Render slides from the `SLIDES` array; build dots; show slide 0.
  - Next → advance; Back → retreat (hidden on slide 0); on last slide the Next button reads **"Let's start 🌸"** and closes.
  - Skip → close.
  - Close (finish or skip): if `!replay` set `localStorage['bloom.onboarded']='1'`; hide overlay; restore focus to the element that opened it; if `!replay` call `showFirstCheckinTip()`.
  - Keyboard: `ArrowRight`/`ArrowLeft` navigate; `Escape` = skip. Focus the slide heading on slide change (for screen readers).
- `showFirstCheckinTip()`: if `Object.keys(entries).length === 0` and no `bloom.tipDismissed` flag and `#first-tip` empty → inject a dismissible banner: "🌸 Tip: start with one check-in today — rate a few things on the 1–7 scale, then Save." with an × button that sets `bloom.tipDismissed`. (If the user later saves data and the banner is still open, it simply stops re-appearing on the next load — `entries` is non-empty then. Acceptable; note it.)
- Load-time init: if `bloom.onboarded` is already set (returning user), call `showFirstCheckinTip()` on load so the nudge also works for existing accounts with no data.

## 7. Auth hook edits (`supabase-auth.js`) — exact

**Edit 1** — in the signup button handler (`signupBtn.addEventListener('click', ...)`), after the `if (res.error) {...}` chain, add one line so both success branches (auto-confirmed session **and** "sign in now" flow) arm the intro:

```js
if (!res.error) {
  localStorage.setItem('bloom.justSignedUp', '1');
}
```

**Edit 2** — in `onAuthChange`, after `applyAuthState`:

```js
if (event === 'SIGNED_IN' || event === 'SIGNED_OUT') {
  await applyAuthState(!!session);
  if (event === 'SIGNED_IN' && window.bloomOnboarding) {
    window.bloomOnboarding.onSignedIn();
  }
}
```

Ordering matters: the intro opens only after `applyAuthState` has pulled cloud data and rendered the Track view, so the app is ready behind the overlay.

## 8. Slide content — comprehensive, one idea per slide

### 8.1 `SLIDES` array copy (agent may refine tone; keep one idea + ≤2 short lines per slide)

1. **Welcome** — `🌸 Welcome to bloom` — "Your private space to check in with how you feel — a few minutes a day."
2. **What a check-in is** — `A check-in takes 30 seconds` — "Pick a time, rate how you're doing, add a line if it helps. That's it."
3. **The 1–7 scale** — `One tap per thing` — "Each tracker runs 1 (not at all) to 7 (extremely). Anchor labels — like *Not at all → Extremely* — guide you."
4. **The defaults** — `Start with 10 sensible trackers` — "Anxiety, sleep, energy, overthinking… grouped by type. Nothing is permanent."
5. **Notes** — `Add context, not just numbers` — "A short note about what happened or what helped makes patterns meaningful later."
6. **Patterns** — `Watch your patterns bloom` — "Visualize turns days into trends: your typical range, time of day, and what helps."
7. **Make it yours** — `Shape bloom to your life` — "Rename or remove trackers, pick a pastel palette, choose light or dark."
8. **Your data** — `Yours, and synced` — "Signed in = your data backs up to the cloud. Export a backup file any time from Manage."

Visual per slide (agent's call): emoji + simple CSS shapes (dots, a mini 1–7 scale mock, a mini trend line) — flat, pastel, consistent with the app's aesthetic. No images/assets to download.

## 9. Design direction (for the aesthetics review)

- Reuse the app's existing design tokens: the palette CSS variables already defined in `palettes.js` / `styles.css` (e.g. `--pink-400`, `--text-soft`, card backgrounds, border radii) — read the actual variable names from those files before writing `onboarding.css`. The overlay must work in **both light and dark theme modes** (`bloom.theme`).
- Font: Nunito (already loaded). Typography: bold heading, soft body color, comfortable line-height.
- Card: centered, rounded (match existing card radius ~12–16px), soft shadow, max-width ~520px, padded for small screens; slides region fixed height so layout does not jump between slides.
- Motion: subtle fade/slide between slides (~200–250ms ease-out); dots animate; **disabled entirely under `prefers-reduced-motion: reduce`**.
- Tone of copy: warm, plain language, no psych jargon, privacy-reassuring. General audience.
- Skip always visible (top-right). Progress = dots, not a bar.

## 10. Accessibility

- `role="dialog"` + `aria-modal="true"`, labelled by slide-1 heading; `aria-hidden` toggled on inactive slides.
- Focus moved into the overlay on open; returned to the opener on close.
- Keyboard: `←`/`→` navigate slides, `Esc` skips, Enter/Space on focused buttons; `:focus-visible` rings consistent with the app.
- Buttons have aria-labels ("Next slide", "Go to slide 3", "Skip intro").
- `prefers-reduced-motion` respected (no slide animation).
- Contrast: body text meets WCAG AA on both theme modes.

## 11. Constraints

- CSP: `script-src 'self'` (plus jsdelivr) → no external libraries, no inline `<script>`; `style-src` allows `'unsafe-inline'`, but keep styles in `onboarding.css`.
- Overlay must not interfere with the auth screen, service worker, or Chart.js.
- Slides render from a single `SLIDES` array (one copy location) unless the agent prefers static DOM — decide explicitly.
- Do not modify `app.js` (works as-is). If a change there truly becomes necessary, flag it instead of silently editing.

## 12. Acceptance checklist

- [ ] Fresh signup → intro appears once, right after sign-in, app rendered behind it.
- [ ] "Let's start 🌸" and Skip both dismiss; `bloom.onboarded` set; nudge banner shows in Track (no data).
- [ ] Sign out → sign back in (same account) → **no** intro, no nudge re-show after data exists.
- [ ] Second account (or cleared storage + signup) → intro shows again.
- [ ] Manage → "Replay intro" opens it; finishing/skipping replay writes **no** flags.
- [ ] `←`/`→`/`Esc` work; focus returns after close.
- [ ] Light + dark themes, mobile viewport (~375 px), installed PWA all render correctly.
- [ ] `prefers-reduced-motion: reduce` → no slide animation.
- [ ] No console errors; no new dependencies; CSP unchanged.

## 13. Latitude for the design agent

**Free to change:** all copy/tone, slide count (if a slide splits or merges cleanly), illustrations, colors within the existing palettes, motion curves/durations (subject to reduced-motion rule), layout details, button styling.

**Must not change:** the trigger flow (post-signup `SIGNED_IN` + flags), the flag keys (`bloom.onboarded`, `bloom.justSignedUp`, `bloom.tipDismissed`), the no-app.js-edit rule, the CSP/no-library constraint, the `onboarding.js` API surface (`onSignedIn` / `start({replay})` / `showFirstCheckinTip`) that `supabase-auth.js` calls.
